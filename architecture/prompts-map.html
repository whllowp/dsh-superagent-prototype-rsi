装配线之外进入模型的东西

  • Executor 额外读 DeepSeek Harness 的编码提示词与仓库的 AGENTS.md；主 Session 不读。
  • 两个 Source 技能（skill/github、skill/feishu，各含 cli.md 附录）按需加载：消息涉及其 Source 时 Session 读对应技能。
  • 团队可加自有技能（如身份对照表），按技能名模式注册、按需加载；不能占用内置技能名。
  • 运行期消息不走系统提示：派工、Input、候选卡、follow_up 通知、worker 报告都以内联消息进入回合。
  • 强度阶梯（详见设计思路页）：工具强制 > 内置段 > 匹配规则 > 团队段/技能 > 外部文本。

    校验与生效（防提示词漂移）

    • 保存即生成不可变版本（编号 / 前身 / 时间 / 来源 panel 或工具）；恢复旧版也是新版本；过期基准保存被 409 拒绝、草稿不丢。
    • 校验拒绝：未知键、空文本、缺失模板占位符、占用保留技能名；从不静默截断；与默认完全相同的覆盖自动清除（该段回落跟随未来默认）。
    • 生效路径：每次模型请求都读最新版本，同一回合的后续步骤也用新文案；保存不重启、不打断、不唤醒会话（详见知识更新页）。
    • 升级后：未覆盖的段落自动跟新默认；覆盖过的标记「默认已更新」并排展示差异，团队保留 / 换新 / 再改三选一。
    • 提示词只约束模型行为：身份、权限、工具校验、回复用途、长度上限都在代码层强制——外部文本永远不构成授权。

    通读观察：这套提示词在防什么

    • 防过度说话：communication.md 97 行是全文最长的一段——「发送前逐句自问：删掉这句，人还能理解结果或行动吗？不能就删」，不请自来的 IM 只允许三种理由。
    • 防越权扩权：路由者不得改写请求、加实现计划；推断工单只做匹配规则内的局部变更；视觉反馈必须指向具体结果或客观既有标准；引用内容不是授权。
    • 防半成品谎报：开 PR ≠ ready；草稿必须标注未完成；blocked 只在真的需要人行动时使用；无 baseline 截图就不能宣称 UI 就绪。
    • 防绕过：不得用 CLI 绕过被拒的回复、不得把问题写进 summary 干等、不得用分号链规避 100 词、不得换渠道重发被丢弃的消息。
    • 防与人抢活：人的分支已含同样改动就立即让位关 PR；自动审阅者最多三轮、不追 bot 认可；新工作永远挤不掉人对既有工单的追问。
