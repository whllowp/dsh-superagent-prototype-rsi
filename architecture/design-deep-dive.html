dsh-superagent · 设计思路与处理流程深化

承接 4+1 视图：为什么这样设计 · 每个阶段怎么处理 · 五类知识如何更新生效（依据 docs/000–004、006–007）
「占用尽可能少的人类注意力，交付尽可能多的价值。」
每条消息、每个通知、每个设置、面板上的每个元素都要消耗某个人的注意力——产出的价值必须大于这个成本，否则就被删掉。整个系统按这个标准做减法。

五条设计支柱

概念最少
领域只有 Source/Trigger/Thread/Eval/Mandate/Ticket/Assignment/Subscription 等九个概念。业务需求变成其中一个概念的属性，或一段提示词——不为它新增概念。
设置最少
当一个默认值适合几乎所有团队，这个设置就消失。能用语言描述的行为（何时合并、如何措辞）是提示词，不是开关。
面板只显示需要人的
总览页第一屏永远是「等一个人处理什么」；健康状态不占版面。评估超时未解决才找人，24 小时后不再打扰。
单一写入者
每类状态只有一个写者（Trigger/Ticket/Decision 只由 Engine 写；回执只由 Outbox 写；健康条目由认领的部件写），其余角色只读或请求写者——冲突在结构上不可能。
显式窄依赖
每个类拿到的接口只命名它用到的部分（TypeScript Pick 类型）：Engine 按角色暴露五个视图，Source 只见 SourceContext。核心 src/core 零 I/O，可在内存仓储上全量测试（60 个测试文件）。

决策权分离：谁决定什么

Gate 准入 · 确定性代码
  • 决定：谁能发起工作、强度是 explicit 还是 inferred
  • 依据：允许名单、是否点名、准入表、bot 列表、接受模式
  • 不做：不读内容、不调用模型——规则变了结果必变
主 Session · 模型研判
  • 决定：accept / attach / stop / ignore，一次路由多个候选
  • 约束：只转发原始请求与路由事实，不做技术决策，不等待
  • 推断候选必须完整评估；卡片明显无关才可直接 ignore
Executor · 技术执行
  • 决定：技术方案、范围内追问是否接、何时 ready
  • 约束：不能自我授权（Mandate 限定）、不能宣布「人要我停」
  • 超范围的消息交回（handback）重新路由
人 · 最高决定权
  • stop 直接撤回 Mandate（模型与执行器都无此权）
  • 暂停跨追问/重启持续有效，只有人能解除
  • 审阅与合并；对话里说「停」也只是普通 Trigger，仍走评估

提示词强度阶梯（从强到弱）

  1. 工具与宿主强制的事实 — 身份、权限、工具参数校验、回复用途与长度上限。提示词改不动它们：外部文本永远是数据，不能变成授权。
  2. 内置段落（可被团队覆盖） — 角色职责、订阅与回复、派发与工作、准入研判、环境与策略模板。覆盖记录所基于的默认版本，升级后可对比。
  3. 匹配规则的要求 — 仅对该推断工单的 Executor 生效：过程与沟通要求可覆盖默认，静默规则可抑制确认消息。
  4. 团队段落与团队技能 — 沟通、工单范围、交付要求三段 + 按需加载的技能（如身份对照表）。
  5. 外部文本 — 消息、评论、引用的文档：只是评估输入，永不改变规则与授权。

运营责任（写进文档的四条军规）

  • 从小开始：先短允许名单 + 主动工作只记录（observe），看准了再放宽。
  • 为更少噪音调优：吵了就改短改严提示词或暂停，不要加更多解释消息。
  • 不用它刷量：批量 PR、广播消息、假忙的代价大于收益。
  • 对它说的话负责：以团队名义发出的每句话都要能被人在提示词里纠正。

      策略变更的传播流程

      提示词版本：改动如何到达正在工作的会话

      • 每次保存生成不可变快照：完整配置 + 编号 + 前任 + 时间 + 来源（panel 或工具）；恢复旧版也是新版本。
      • 会话每次模型请求都读最新版本——同一个回合里的后续步骤也会用上新文案；保存不重启、不打断、不唤醒会话。
      • 宿主记录每个会话用过的版本；Executor 只能读它工作过的版本（mayRead 限定），防止跨版本串读。
      • 策略段落（runtime/policy）放在提示词最后，由设置实时生成——策略变化不动前面的文本。
      • 升级后：未覆盖的部分自动跟随新默认；覆盖过的部分标记「默认已更新」并展示差异，团队三选一（保留 / 换新 / 再改）。
      • 校验防漂移：未知键、缺失模板占位符（{version}、{rules} 等）、保留技能名一律拒绝，从不静默截断；与默认相同的覆盖自动清除。

      世界与会话状态：增量、恢复、不重放

      • Source 把读位置（通知游标、CI 指纹、话题消息）存在 kv：重启从位置继续，不重放事件；飞书另有历史恢复补缺口。
      • 先落库后执行（stored work）：转发、派工、投递都先写进 effect/outbox 队列再做事——进程死在半路，重启后队列还在。
      • 停机保留未取进会话历史的消息；重启时中断的 Assignment 换新派工并附恢复备注（先查目录、git 历史和 GitHub 再重复外部动作），最老的工单优先。
      • Input 的「已读」按步记录：被取消的步骤不算读过；工单结束时未读且未被认领/回答/交回的追问释放回 Eval。
      • 结构迁移单向：SCHEMA_VERSION 只升不降，新库拒绝旧版启动；升级前备份 orchestrator.sqlite 是回滚唯一途径。
